Model Capability Resolver PROTOTYPE

The question this answers: the pipeline currently builds one OpenRouter request shape and assumes every image model reads it the same way. It doesn't. meta/muse-image accepts resolution, seed and aspect_ratio without complaint and then ignores or mangles all three, so a caller asking for a reproducible 16:9 image quietly gets a non-reproducible 3:2 one. qwen/qwen-image-3-pro honours all of them but is refused outright by Alibaba moderation on maps with national borders. So: should the pipeline keep one request builder and hope, or should each model declare what it honours and the resolver report every downgrade out loud? Press the buttons and see whether being told "your seed was dropped, this run cannot be replayed" feels like the right contract.

All capability data below was measured against the live API on 2026-08-31, not read from documentation — meta/muse-image's endpoint listing is empty.
