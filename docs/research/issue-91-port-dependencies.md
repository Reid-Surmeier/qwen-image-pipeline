## Exact Assembly dependency chain

`assemble_one` → `dynamic_blocks` → `place_donor` → `alpha_crop` → `new_leaders` → `render.draw_block`; source preparation uses `load_source` → `clean_template` → `render.make_erase_mask`, OpenCV inpainting, `render.synthesize_scan_background` and seeded `row_paper`. Verification uses `render.make_region_mask`, exact NumPy pixel comparison, Tesseract `--psm 11`, `render.normalize`, and lossless reopen comparison.

Preserve `slug`, `words`, `phrase`, `line_regions`, `padded_regions`, `row_paper`, `alpha_crop`, `place_donor`, `dynamic_blocks`, `new_leaders`, `page_ocr` and `assemble_one`. From `render.py`, preserve `sha256`, `normalize`, `font`, `line_width`, `wrap`, `make_erase_mask`, `make_region_mask`, `synthesize_scan_background`, `draw_block` (including its nested drawing function). Its separate prototype `render()` and `main()` are not called by the gallery.

Application recipe data currently embedded in `assemble.py`: `PRODUCT_REGIONS`, `PRODUCT_CLEANUP_REGIONS`, `OLD_LEADER_ERASE_REGIONS`, `OLD_LEADERS`, `BANNED`, `VARIANTS`, `KODAK_CATEGORIES`, `KODAK_CALLOUTS`, `KODAK_ANCHORS`. These are not general image requirements. The existing creative code still includes Kodak/Canon/product-family branches: stripping those branches would change the saved procedure. Preserve them for that explicit recipe; do not advertise them as support for arbitrary new templates. `layouts.json` is application data, including JP2 source paths and five explicit Nimbus font files. No application source image or font needs to be copied into the central tool.

Output order is source clearing → donor extraction/placement → leaders → deterministic text → lossless WebP final and JPEG preview → actual pixel/OCR checks. `assemble_one` writes `accepted=False`, visual/blind verdicts `pending`, even when machine checks pass. Assembly uses OCR ≥0.70; the saved final validator requires ≥0.75. Preserve both distinct stages. `finalize_reviews.py` contains historical approvals and must not be exposed as a way to approve new results.

Runtime dependencies observed available on this host: Pillow, NumPy, OpenCV, Tesseract. Their presence is not portable dependency packaging; an installed tool must declare/check them. Final byte parity also depends on the original font and image-library versions. Original `assemble_one` has a resume path with `fitResults=[]`; a saved manifest may therefore lack text-fitting evidence even though its image was previously rendered.

## Existing Seedance executable pointer

The canonical target already contains `seedance/src/seedance_icons/cli.py` and `openrouter.py`; it is a separate Python package, not part of `qwen_ui_pipeline`. `seedance/pyproject.toml` exports `seedance-icons`; equivalently run `PYTHONPATH=<tool>/seedance/src python3 -m seedance_icons.cli`. Retain its `capabilities → plan → submit → wait → verify` sequence and application `--runs` destination. `plan` accepts the recorded explicit `--waive-strategy-gate` reason; no new default waiver is implied. `submit` checks exact decimal cost acknowledgement, request hash, live canonical model and prior strategy record, and persists possibly-spent state before sending. Existing tests live under `seedance/tests/`.

The currently installed shared Qwen umbrella contains no Seedance route; it loads the old Maga/ComfyUI image snapshot. The sculpture bundle proves a successful Muse→Seedance run and explicit motion-reference waiver, but not the exact invocation used. Preserve the available Seedance CLI and its gates rather than inventing a new caller or implying that the waiver passed the missing-reference gate.
