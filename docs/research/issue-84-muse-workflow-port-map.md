# Recover the Muse workflow and its gates from existing DIS work

Research for [Recover the Muse workflow and its gates from existing DIS work](https://github.com/Reid-Surmeier/Image-generation-pipline/issues/84), 2026-09-09. Planning only: no provider calls, asset copying, source edits, or visual acceptance. Target inspected at `018bddd` on `build/v0.3.0`.

## Finding

There is substantial working Muse code to port, but no single installed “Muse DIS pipeline” contains it all. The source is distributed across application worktrees, a shared OpenRouter client in a Qwen prototype checkout, accepted issue decisions, and recorded generation/review runs. The strongest invented-product implementation is the thirty-ad gallery, not the original DIS repository's `main`. Generic image edits and the sculpture viewer use Muse without the invented-product logic. This inventory identifies a faithful port's sources; it does not certify that every historical gate is production enforcement.

The owner's desired routing is Muse for image generation and Seedance for icon animation, without a special trigger phrase. Application repositories retain their assets and records. That routing does not make fictional-product invention, DIS photography, Kodak/Canon templates, or commercial-brand removal requirements appropriate for every image.

## How the existing product-ad run works

1. **Read the source ad and invent the product.** The source-locked Kodak/Canon [READ and reference specification](https://github.com/Reid-Surmeier/vibe-dis-composites/tree/6c1ac2cad9213823183d23823fe30d50b882678d/docs/supplied/15-invented-product-reference-ads) supply composition and typography. The [accepted product-packet decision](https://github.com/Reid-Surmeier/vibe-dis-composites/issues/34#issuecomment-5503336473) accepts six invention modes, compatible twists, serious copy, a matching fictional DIS company, and seed replay. It explicitly excludes DIS Images photographs. The original HTML does not call Muse.
2. **Prepare bounded donor requests.** [`prepare.mjs`](https://github.com/Reid-Surmeier/vibe-dis-composites/blob/6c1ac2cad9213823183d23823fe30d50b882678d/tools/prototypes/invented-product-gallery/prepare.mjs) extracts that engine, selects six packets and ten donor strategies, validates the packets, writes exact prompt hashes and a ten-attempt preflight. Prompts request product imagery on a neutral catalog background, with no page, typography, logos or readable text. These are text-to-image requests; the found-ad scan is not sent as a donor reference.
3. **Generate one named donor.** [`generate.py --attempt NNN`](https://github.com/Reid-Surmeier/vibe-dis-composites/blob/6c1ac2cad9213823183d23823fe30d50b882678d/tools/prototypes/invented-product-gallery/generate.py) admits only planned IDs, refuses existing submission/run records, verifies prompt hashes, writes `submission.json` before one Muse request, and records cost, output hashes, provider task identity when present and possible billing failure. The fixed historical request is `meta/muse-image`, `n=1`, `1760x1440`, through OpenRouter. These historical scripts must not be rerun casually: their records represent spent attempts.
4. **Assemble and check the ad.** [`assemble.py`](https://github.com/Reid-Surmeier/vibe-dis-composites/blob/6c1ac2cad9213823183d23823fe30d50b882678d/tools/prototypes/invented-product-gallery/assemble.py) imports deterministic helpers from `ad_typeset_transfer/render.py`, consumes `layouts.json`, replaces source product/identity regions, places donor pixels, draws leaders and typesets copy. It measures changed pixels outside declared masks, OCR token coverage, banned source words and lossless round-trip. The source dimensions are 5266×6437 and 10532×6437; these are application template dimensions, not generic Muse requirements.
5. **Review exact files and retain rejected versions.** [`validate.py`](https://github.com/Reid-Surmeier/vibe-dis-composites/blob/6c1ac2cad9213823183d23823fe30d50b882678d/tools/prototypes/invented-product-gallery/validate.py) requires thirty unique accepted outputs, five strategy families, donor and output hashes, size, recorded checks and blind verdicts. [`finalize_reviews.py`](https://github.com/Reid-Surmeier/vibe-dis-composites/blob/6c1ac2cad9213823183d23823fe30d50b882678d/tools/prototypes/invented-product-gallery/finalize_reviews.py) binds specific historical review groups to exact hashes. The [gallery issue](https://github.com/Reid-Surmeier/vibe-dis-composites/issues/41) records multiple correction/review rounds and later identity revisions. This research read those records; it did not repeat the visual review or promote a candidate.

## Different procedures must remain distinguishable

**DIS-photo composites:** [`ad_composite.py`](https://github.com/Reid-Surmeier/vibe-dis-composites/blob/60d9827719bc3254ba83fd2edd5b50ad1f8aa2a7/tools/ad_composite.py) accepts an application `spec.json`, ordered references, source-relative paths or `dis:<photo-id>`, a prompt and size. The default content guard restricts the ad reference to photographic language/layout/typesetting, not its people/mascots/brands. It supports a second refinement pass over the previous generated frame with specific no-paper-aging and no-retypesetting instructions. It detects actual PNG/JPEG/WebP signatures because Muse outputs previously stored with `.png` names contained WebP bytes. Each attempt gets its own directory, correcting earlier overwritten provenance. Reference order, authority and those prompt lessons are meaningful behavior to preserve.

**Invented-product ads:** use product-packet logic and deterministic typesetting, explicitly excluding DIS photographs. [The repeatable-ad decision ticket](https://github.com/Reid-Surmeier/vibe-dis-composites/issues/36#issuecomment-5503378926) corrects a prior mix-up: its running-woman/photo state prototype belongs to the photo-composite map, not the invented-product map. Conflating these workflows would repeat an already documented mistake.

**General source edits and UI assets:** the [3M source edit](https://github.com/Reid-Surmeier/vibe-dis-composites/tree/92e41053e3f7a034412e4b6b74e3609717e9a7df/docs/prototypes/issue-56-3m-dis-collage) and [e-ink runner](https://github.com/Reid-Surmeier/vibe-dis-composites/blob/8767097d446a7f817438b6c0af8617b45b9af59c/tools/prototypes/muse_eink_curve/generate.py) accept protected reference edits rather than invented products. [The recent image-viewer issue](https://github.com/Reid-Surmeier/vibe-dis-composites/issues/88) similarly specifies one Muse frame pass, artwork preservation and deterministic source Assembly. Its issue body alone does not identify a committed runner, so the exact recent UI caller remains unverified.

**Layered typography experiments:** [`proto_typeset/layered.py`](https://github.com/Reid-Surmeier/vibe-dis-composites/blob/60d9827719bc3254ba83fd2edd5b50ad1f8aa2a7/tools/proto_typeset/layered.py) exposes page/column/detail passes, crops, feathered replacement, a historical 45-attempt cap and OpenRouter Gemini readback. This differs materially from product-gallery rules that prohibit generated final text. Its cap and automatic paid readback are not standing permission for the central tool. [`gen_image.py`](https://github.com/Reid-Surmeier/vibe-dis-composites/blob/60d9827719bc3254ba83fd2edd5b50ad1f8aa2a7/tools/proto_typeset/gen_image.py) is another explicitly throwaway wrapper that downsizes references to a 2048-pixel maximum edge.

## Gates: actual enforcement versus recorded intent

| Gate | What code actually establishes | Port implication |
| --- | --- | --- |
| One predeclared request and no duplicate | Gallery and source-edit runners check existing receipts and persist submission before calling. Checks use ordinary existence/write operations, not an atomic cross-process reservation. | Preserve one-attempt semantics; do not call these wrappers concurrency-safe. Reuse the target Run Record reservation rather than inventing a competing ledger. |
| Spend ceiling | Gallery preparation creates exactly ten attempts; each request asks for one output. Validator later limits completed donors/cost. Old `ad_composite.py --frames` has no aggregate ceiling. | A historical ten-entry plan is not a reusable global budget gate. Keep application allowance and reserve through the target procedure. |
| Reference locking | Source-edit runners check complete input/prompt hashes. Composite runner checks existence but records truncated reference hashes after calling. Generic wrapper resizes references without a full payload-reference hash inventory. | Preserve intended input preparation; explicitly inventory original and transmitted bytes. |
| Ambiguous failure | Gallery and source-edit receipts block reusing the same attempt. Composite and benchmark wrappers record after submission and lack equivalent durable interruption evidence. Layered runner blocks `submitted` entries, but its ledger loader does not block all `ambiguous_failure` entries. | “Never blindly retry” prose is stronger than some legacy implementations. Report this gap, do not silently weaken target gates. |
| Provider route | Shared client makes one OpenRouter request. Gallery and source-edit request bodies do not explicitly include `provider.allow_fallbacks=false`, even where records say fallbacks are disallowed; layered requests do include it. | Provider routing intent and actual transmitted payload need separate compatibility checks. |
| Fidelity and OCR | Gallery Assembly measures actual source/output pixel differences and OCR; Assembly uses coverage ≥0.70, while validator requires ≥0.75. Validator rehashes files but trusts recorded fidelity/OCR fields. | Preserve measured evidence and stricter final acceptance; do not present manifest booleans as independent remeasurement. |
| Blind visual review | Historical exact-hash assignments and rejected rounds exist. `finalize_reviews.py` embeds those particular groups/hashes and writes pass flags. | Port the review contract, not the ability to stamp old approvals onto new outputs. Human approval stays separate. |

These conclusions come from the pinned scripts linked above. They are source inspection findings, not new runtime or concurrency test results.

## Sculpture reuse and its exception

The committed [Muse spec](https://github.com/ReidSurmeier/figma-ui-ux-qwen-pipeline/blob/e23b375047e8e8269df5ff2becc21516f646fde7/references/statue-control-motion/muse-spec.json) sends a six-cell control atlas for a restrained silver/glass finish. It contains no seeded product invention, catalog strategy or DIS-photo rules. The [provenance](https://github.com/ReidSurmeier/figma-ui-ux-qwen-pipeline/blob/e23b375047e8e8269df5ff2becc21516f646fde7/references/statue-control-motion/provenance.json) records one Muse output ($0.01), resized from 2048×1152 to a 1280×720 anchor, then one Seedance output ($1.39635), with identical first/last anchors and no audio. It describes extraction of 24 actual video frames per control into Godot AtlasTexture assets.

The [Seedance plan](https://github.com/ReidSurmeier/figma-ui-ux-qwen-pipeline/blob/e23b375047e8e8269df5ff2becc21516f646fde7/references/statue-control-motion/plan.json) explicitly says the required matching video-reference gate failed and was waived because the local capture was not a suitable public HTTPS reference. The run is evidence of useful Muse→Seedance→Godot reuse, not proof of passing that gate. The committed run bundle does not establish which Muse CLI invocation produced it; shared spec shape is insufficient proof of its exact caller. The application checkout has unrelated dirty agent configuration, which this research did not touch.

## Minimum faithful port, subject to specification

1. Preserve a source manifest of these exact commits, public entry points, prompt templates, request construction, reference transforms, output formats and gate semantics. Use recorded inputs/outputs and unpaid mocked-provider checks to compare port behavior before any paid evaluation.
2. Bring the shared OpenRouter image call into the target's existing durable Run Record/procedure path with Muse as the image default. Remove hardcoded external-checkout imports. Every necessary safety adaptation must be named; “exact port” cannot honestly mean byte-identical application scripts and unchanged unsafe receipts.
3. Preserve composite/refinement and general-edit behavior as distinct callable modes. Keep DIS corpus resolution and project-specific source selection in the application. Do not append advertising content bans to arbitrary UI edits.
4. Preserve accepted product engine logic, donor prompt construction and reusable Assembly/type helpers where central invocation needs them. The Kodak/Canon READs, layouts, fonts, hardcoded masks, specific products, assets and historical review verdicts remain application-owned inputs/evidence. Scope of generic typography experiments is still a decision, not implied by porting the product gallery.
5. Compare the new invocation against the photo-composite, product-gallery and general-edit cases, separately. Keep Seedance's established verification path and explicitly decide the old video-reference waiver policy. No historical budget exception or visual approval becomes a default.

The tool/application ownership above already agrees with [ADR 0006](../adr/0006-adopt-v0.3-successor-governance.md). Existing paid-route and Assembly rules remain in [ADR 0003](../adr/0003-bound-paid-verification-to-openrouter.md) and [ADR 0001](../adr/0001-separate-rendering-from-assembly.md). Their Qwen-specific text will need an explicit migration decision; this research changes no ADR.
