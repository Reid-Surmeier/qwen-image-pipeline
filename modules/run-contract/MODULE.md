# Run Contract

- Purpose: Turn valid planning documents and proved references into one canonical immutable Planned Run.
- Interface: `modules/run-contract/index.ts`
- Errors: `modules/run-contract/errors.ts`
- Acceptance: `modules/run-contract/run-contract.test.ts`

Run Contract rejects secret material, a mismatched Tool Lock, an unsupported locked version profile, unapproved Procedures, unsafe paths, unprovable counts, budget excess, invalid correction ceilings, and malformed successor relationships before sealing a Run Request. Production planning obtains identity through `filePlanningIdentity(installedToolArtifactRoot)`, which verifies the closed `tool-artifact.json` inventory, every listed file hash, the aggregate artifact SHA-256, and the fixed `RELEASE`, `COMMIT`, and `VERSION_PROFILE.json` files before issuing a privately branded identity service. Caller-asserted identity objects, unlisted files, symlinks, path escapes, and integrity drift are refused. The derived release, commit, artifact SHA-256, Procedure version, Run schema version, and adapter protocol version must match the application Tool Lock exactly. `verifyPlannedRunIdentity` repeats that exact three-way check across the immutable Planned Run, the current application Tool Lock, and the verified installed identity before advancement can reserve an attempt. The selected Procedure record must declare that same Procedure version. Count and budget checks price the maximum possible paid effect, not the number of outputs a provider eventually returns. The Project Contract fixes `artifactRoot` and `maximumCorrectionRuns`; both become immutable Run Request evidence. The current Run Request schema is version `2`; its application-owned `artifactRoot` is required. A successor relationship is part of the canonical request rather than side data supplied during reservation.

A Qwen Image Objective may declare an Assembly plan. When present, `required` is exactly `true`; `baselineReferenceSlot` names a locked image reference; the single integer `ownedRegion` stays inside that reference's inspected dimensions; and `exactCopy` contains one or more pixels inside the region. Each pixel SHA-256 binds `JSON.stringify({ x, y, rgba })` after Run Contract has normalized those three fields. Invalid shape, hash drift, and out-of-region evidence fail with `ASSEMBLY_PLAN_INVALID`.

A Seedance Objective must declare a Video Plan. Assembly may be absent only when its exact machine-readable decision says `required: false` and `pixelOwnership: "none-authoritative"`; a vague or missing assertion is refused. The same plan freezes expected width, height, duration, and audio presence for independent output verification. Qwen objectives cannot carry a Video Plan, and Seedance objectives cannot carry a Qwen Assembly plan.

Run Contract owns canonical serialization and the request SHA-256. It does not reserve an attempt or persist a Run Record.
