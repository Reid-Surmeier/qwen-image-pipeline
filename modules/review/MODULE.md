# Review

- Purpose: Bind independent review evidence to the exact candidate and contract.
- Interface: `modules/review/index.ts`, `modules/review/interface.md`
- Errors: `modules/review/errors.ts`, `modules/review/errors.json`
- Acceptance: `modules/review/review-packet.test.ts`, `tests/test_successor_governance.py`

Review owns the Standards/Specification review gate and the blind application-artifact review procedure. It prepares a hash-locked application packet only after Run Record replay proves a deterministic `verified_candidate`; caller-selected pass strings and caller-selected application revisions have no interface. Its branded file adapter derives the current application commit from the application Git repository and reads the contract, review brief, and references from that same rooted repository snapshot. The packet embeds the canonical Run Request, event head, tool/application commits, acceptance contract, hash-locked review brief, references, replay-authenticated candidate and checks, instructions, and unresolved decisions. Validation re-derives every field, enforces the complete packet shape and Approval separation, rereads current application evidence, and replays Run Record evidence, so rehashed clones and changed bytes, contracts, briefs, commits, requests, events, candidates, or checks invalidate it. An explicit counterexample operation can issue opaque evidence only after an authentic packet catches a deliberate reference mutation; that evidence is bound to the source Run, packet, proposed rule, affected seam, and mutation description. Review records evidence and verdicts; it cannot waive deterministic failures, call independent or paid semantic review, or create application Approval.
