# Video Verification

- Purpose: Independently inspect completed Seedance bytes and prove their hash, media shape, duration, audio expectation, counts, and cost state before classification.
- Interface: `modules/video-verification/index.ts`
- Errors: `modules/video-verification/errors.ts`
- Acceptance: `modules/video-verification/video-verification.test.ts`

Video Verification consumes persisted output bytes rather than provider claims. It independently parses the MP4 hierarchy, requires exactly one video track, validates every dense `stsd` sample description and `stsc` selection, recognized video and audio codecs whose kind agrees with each track's declared handler, mutually consistent timing/chunk/sample tables, chunk offsets, and non-empty media data. It then requires a complete FFmpeg 6 framehash decode of those exact bytes from standard input and uses that independent evidence for dimensions, duration, and audio presence. Container metadata must agree with decoded truth before those properties are measured against the immutable Video Plan. Marker-shaped bytes, malformed or undecodable streams, ambiguous video tracks, falsified metadata, unknown sampled tracks, later-description audio, audio codecs relabeled under a non-audio handler, incomplete output sets, duplicate paths, changed hashes, and runtime-invalid cost states fail as typed evidence errors; a bad or hidden audio track is never silently reclassified as no audio. Its interface preserves `VideoVerificationError` as a runtime value for consumers that inspect the documented error class. This parser is deliberately separate from Reference Planning's intake inspection so a planning assertion cannot grade the generated output. A result is classified only when every deterministic check passes. It does not submit or poll a provider, write the Run Record, perform Assembly, or grant subjective visual approval.
